# Аудит: что влияет на оценку, как считается итог, как работает API

Дата: 8 ноября 2026. Проверено кодом, тестами (37 + 14 на PostgreSQL), E2E в браузере (10/10), axe-core (WCAG 2.1 AA: 0 нарушений) и тремя прогонами DEV.

## 1. Что влияет на итоговый балл (по порядку прохождения)

| Шаг | Где | Что проверено |
|---|---|---|
| Транскрипт → `[i] (MM:SS) РОЛЬ: текст` | `transcript.render` | Индексы совпадают с исходным массивом; время от начала диалога, исходные метки сохраняются в данных. |
| Метрики (код, без модели) | `transcript.metrics` | Первая реакция — от системного «Эскалация/перевод на оператора» до первой реплики оператора (порог 3 мин передаётся модели). |
| Схема ответа строится из чек-листа | `prompts.criterion_schema` | Модель физически не может вернуть N/A там, где он запрещён, или ступень вне шкалы. |
| Правила применения (guidance) | `checklist_default.json` | Подобраны на DEV: c02 (N/A если данных хватало), c04 (передача специалистам с каналом = 20), c05 (эмпатия ≠ неотвеченный вопрос), c06 (ожидание = пауза в чате), c07 (итог в прощальной реплике). |
| Проверка цитат | `transcript.verify_evidence` | Дословно в реплике с индексом (кавычки «»/"", ё/е, многоточия); неверный индекс исправляется; выдуманная цитата → повтор (до 2), затем «низкая уверенность». |
| **Голосование** | `engine.judge_criterion` | Если уверенность < 0.95 — ещё 2 независимые оценки, большинство (шкала без большинства — медиана). На DEV уверенность ≥ 0.95 верна в 99%, ниже — в 68%; голосование включается на ~8% критериев. |
| Подсчёт итога | `scoring.compute_score` | Да = полный вес, Нет = 0, шкала ∝ весу (верхняя ступень = вес), N/A → вес перераспределяется (максимум 100), итог округляется до 2 знаков ROUND_HALF_UP; нет применимых — итог `null`; грубая ошибка — отдельный флаг, итог не меняет. |
| Апелляции | `features.recompute` | Решение проверяющего накладывается на исходные ответы модели, итог пересчитывается той же функцией и той же версией чек-листа. |
| Обучение на апелляциях | `storage.appeal_examples` | 3 последних решения по критерию в промпт; **исключены** апелляции по самому оцениваемому диалогу (иначе утечка ответа) и тестовые («E2E…»). |

## 2. Найдено и исправлено

| # | Проблема | Риск | Исправление |
|---|---|---|---|
| 1 | Подсветка: одна фраза, процитированная несколькими критериями, оборачивалась в `<mark>` вложенно (до 5 уровней) | Визуальный баг, нечитаемый контраст | Интервалы цитат объединяются, разметка один раз |
| 2 | Решения по апелляциям на тот же диалог попадали в промпт при переоценке | Утечка «правильного ответа», нечестная оценка | Исключение диалога из примеров |
| 3 | Прогресс пакетной оценки — только в памяти процесса | На Cloud Run опрос может прийти в другой экземпляр → 404 | Прогресс сохраняется в БД после каждого диалога |
| 4 | Фоновая задача без ссылки | Может быть собрана GC | Ссылка хранится до завершения |
| 5 | `group_id` подставлялся в URL без проверки | Подмена параметров запроса к API организаторов | Валидация `[A-Za-z0-9_-]{1,64}` + `quote()` |
| 6 | Повторы при 429 от провайдера — фиксированная пауза, 3 попытки | Сбои пакетной оценки под нагрузкой | 5 попыток, экспонента с разбросом, на 429 длиннее |
| 7 | Ошибки HTTP в разных форматах (`detail` / `error`) | Непоследовательные сообщения в UI | Единый формат `{"error": …}` |
| 8 | Публичная ссылка без входа тратит деньги на модель | Расходы | Дневной бюджет `DAILY_BUDGET_USD` (429 с понятным текстом) и лимит запросов с IP `RATE_LIMIT_PER_MIN`; просмотр всегда доступен |
| 9 | SQLite стирается при редеплое Cloud Run | Потеря апелляций и версий чек-листа | PostgreSQL по `DATABASE_URL` (Cloud SQL), SQLite локально |
| 10 | Контраст текста 3.0–3.5:1, `select` без подписей, чат не доступен с клавиатуры | WCAG 2.1 AA | Токены цветов, aria-метки, роли, фокус, `prefers-reduced-motion` |
| 11 | `update_appeal` принимал любые имена колонок | Потенциальная SQL-инъекция через имя поля | Белый список колонок |
| 12 | Гонка за номер версии чек-листа при одновременном сохранении | Ошибка 500 | Повтор со следующим номером |

## 3. Известные ограничения

- Эталон DEV размечен командой, не организаторами. Самые спорные трактовки: c07 (прощание без итога = «Нет»), c02 (N/A, если данных хватало).
- Диалог без реплик оператора не описан в чек-листе — модель оценивает отсутствие действий по общим правилам.
- Метрика «первая реакция» у звонков приблизительна (метки — момент распознавания реплики).
